# 品牌资产：名字、标语、图标、社交预览图

## 名字：`书斋` 不改，理由是硬的

`shuzhai` 这个字符串**锁在两个改不了的地方**：

| 在哪 | 改了会怎样 |
|---|---|
| `package.json` 的 `name` | 它决定 `app.getPath('userData')`，也就是 `%APPDATA%\shuzhai\library.db`。改名 = 应用在一个空目录里重新开张，**阅读进度和书签全没**（铁律 3，重扫恢复不了）。上一次搬迁是**写了迁移**才做的，见 AGENTS.md 开头 |
| `builtin-themes.ts` 的 `shuzhai-day` / `shuzhai-night` | 那是用户选中主题存进 localStorage 的**键**。改了等于所有人的主题静默失效，`builtin-themes.test.ts` 有一条钉着这四个 id |

所以显示名换成别的（`读过`、`藏书印`、`翻过` 这类）**买不到任何东西**：
数据目录和主题键仍然叫 shuzhai，只会重新造出「应用叫 X、目录叫 shuzhai」
那种文档陷阱——那正是刚花力气修掉的一个。

**差异化不靠名字，靠标语。** 名字负责气质，标语负责说清这东西干嘛。

## 仓库名：`shuzhai`，不带序号

`shuzhai` 已经是这个项目的规范机器名（包名、数据目录、主题前缀），仓库直接沿用。

⚠️ **序号是系列的记账，不是产品的一部分。** `github.com/rockbenben/shuzhai` 这串
出现在下载链接、别人转贴的那一行、搜索结果里，而一个编号对读者不说明任何事——
同 `repo-facade` 那条「一句话前面不挂系列编号」：读者最缺耐心的位置不该塞一句
与他无关的话。系列归属由首屏那枚徽章和页脚说，不必再往名字里塞一遍。

⚠️ **改名要连 README 首屏那个「⬇ 下载」一起改**——那是整份 README 最该点得下去的
一个链接，而它指的正是这串。改过一次名而漏了它，那个链接就是死的。

## ⚠️ 标语错了五版，每一版换来一条判据

| | 写的什么 | 错在哪 → 判据 |
|---|---|---|
| 一 | 哪本烂尾了，点开之前就知道 | 照着**设计文档**写，不是照着产品写。当时刚量过：评分 1 本、短评 0 条、标签 0 个 → **别拿零使用的功能当主张** |
| 二 | 一文件夹 txt，摆成一座书斋 | 品类描述。「指个文件夹出书架」legado、静读天下、Readera 都能照抄 → **别的阅读器能照抄的，就不是特点** |
| 三 | 几千本 txt，原地成一座书斋 | 「原地成库」是写代码的人的词 → **用用户的词** |
| 四 | 几千本 txt，本本都有目录 | 目录是**功能**不是定位，而且是所有阅读器的标配 → **定位不是功能** |
| 五 | 几千个 txt，自动摆成一架子书 | 「一架子书」太虚，不知道到底得到了什么 → **画面要具体到能想象** |

**还有一条最要紧的**：这五版之前我从没读过 `novel-manager-spec.md` 的第一页，
而定位就写在那儿——**先读需求正本，再想文案**。

## 定位（来自 spec 第一页）

> 本地 txt 小说库的**管理工具**。以**本地文件为唯一事实来源**，
> 不做在线阅读、不做书源爬取聚合。

加上铁律 2「不存正文，正文永远从原 txt 按偏移量读」——**这个程序不占有你的书**。
对手各占一头：Calibre 把书**拷进自己的库**、legado 靠**书源**在线找、
微信读书起点书在**别人服务器**上。只有它能说：书没动过地方。

**但定位不等于 slogan。** 普通用户没被云端下架过书、也不知道 Calibre 会拷贝文件，
拿这个当钩子他 get 不到——定位是「凭什么信」，该待在副文里当定心丸。

## 定稿

| 用在哪 | 文本 |
|---|---|
| **标语** | 你的文件夹，就是你的书斋 |
| **社交卡副文** | 有封面、有目录、记得你读到哪。<br>读完打个分，下次不用再想「这本我看过没」。 |
| **GitHub description** | 你的文件夹就是你的书斋：txt 小说自动配封面、切目录、记得你读到哪，读完打个分，下次不用再想这本我看过没 |

**评分的说法也换过**：「烂尾了别看」是小众场景，
「**这本我看过没**」才是藏书多的人都有过的那个瞬间——不用解释。

**description 只写中文，不做双语。** `repo-facade` 的判据是「仓库接不住的语言
不要出现在 description 里」——这个应用界面全中文、内容是中文网文、没有
`README.en.md`，配半句英文只会把英文读者引到他用不了的东西上。

topics 建议（终端用户 app 用**用途词**，实现技术排最后或不放）：
`novel` `ebook` `txt` `epub` `reading` `book-manager` `local-first` `windows` `desktop`

# 图标与社交预览图

设计源文件是这里的 `.html`，**产物提交进仓库**，平时不用重新生成——
和更早那个 `scripts/make-icon.mjs` 的约定一样（**那个脚本已经不在仓库里了**，
现在用的是下面 html-shot 那套，别去 `scripts/` 下找它）。

## 想法：一本书，压着一道朱红的书签

⚠️ **这是第三版。** 前两版是「一方藏书印」和「一个文件夹，里面立着书脊」，
换掉它们的理由都记在下面——**负结果留着，不然下一轮又会走回去**。

画什么由一个问题决定：**这个应用真正保管的是什么？** 铁律 3 说得最准：
书和章节都能重扫恢复，**唯独你留下的痕迹不能**——读到哪、书签、划线、评分。
所以画一本安静的书，加一道响亮的朱签；签停在 78% 而不是正中，
那个位置本身就是「读到哪」。

三条刻意的选择：

- **主体必须是亮的。** 深色任务栏是用户的实际环境，纸色 L*≈93 在上面是一块亮的。
  这条不是新的，是上一版量出来的，照搬。
- **全图只有一处红。** 朱签是唯一的强色，也是唯一的落眼点——16px 上认得出的
  就是「亮书 + 一道红」。
- **书脊上四针眼订线。** 这是整张图里唯一「只属于书斋」的一笔：去掉它，
  剩下的是一张任何阅读器都能拿去用的「书 + 书签」。它也正好是小尺寸要去掉的东西
  （32px 以下只糊成一条脏线）——两张画分开存在的理由又多了一条。

### 换掉的那两版

| | 一方藏书印 | 文件夹里的书 | **书 + 朱签**（现在） |
|---|---|---|---|
| 说的是什么 | 「这些书我收着」 | 「书在你自己的目录里」 | 「你读到哪、你怎么评的」 |
| 那属于哪一层 | 所有权 | **凭什么信** | **你得到什么** |
| 16px | ✗ 印糊成一个红点 | ✓ | ✓ |
| 深色任务栏 | ✓ | ✓（上一版翻过明暗才成立） | ✓ |
| 撞不撞脸 | ✓ 少见 | ✗ **和资源管理器撞** | △ 阅读器都爱用书 |

**换掉文件夹的理由是它画错了主语，不是它不好看。**
文件夹说的是「不导入不上传、书在你自己的目录里」——那是**凭什么信**。
本文件上半部分早就为**标语**论证过这件事（定位是定心丸、该待在副文里；
普通用户没被云端下架过书，拿这个当钩子他 get 不到），
**然后图标又照着定位画了一遍**——同一条判据在两个地方给出了相反的结论。
这次让图标跟上：定位归副文，图标画用户得到的东西。

顺带一条更实际的：上一版自己在对照表里给文件夹记的独特性就是「△ 满大街」，
而它要待的地方正是任务栏，旁边就是资源管理器。

**这一版认下的代价**：「一本书 + 书签」是阅读器的通用符号，独特性不如一方红印。
四针眼是拿来补这一刀的——**它是这张图里唯一不通用的部分**，
所以下次谁想「简化一下」把它删了，删掉的是这张图仅有的辨识度。

## 两张画，不是一张缩小

`sizes.png` 是体检结果。结论没变，只是换了内容：**48px 是两张画的交界，
所以两张的几何必须逐个坐标相同**，差别只许在「有没有那几笔细节」上——
比例一变，用户会在那个尺寸上看出跳变。

| | 大图（48+） | 小图（16 / 32） |
|---|---|---|
| 书身 / 书脊 / 朱签的坐标 | 完全一致 | 完全一致 |
| 渐变 | 有 | 平涂 |
| 四针眼订线 | 有 | **没有**（32px 以下糊成一条脏线） |
| 书口那叠页 | 有 | **没有** |
| 描边 | 2.6 | 3（小尺寸要更咬得住轮廓） |

16px 上量出来的四块——这是选这张画的全部理由，**只有四块，而且每块都过 2px**：
书脊 3.0px ／ 纸 4.5px ／ **朱签 3.5px（落眼点）** ／ 签右边那条纸 2.4px。

⚠️ **书要顶满画布。** 上一稿书身只有 76/100 宽，16px 上就少掉一整像素，
四块里最窄那条直接糊没。现在是 84/100。

## 社交卡也换了主张，不只是换了皮

**「书很多」不是主张。** 最早那版右边是一墙封面，说的就是这个——
而 Calibre、legado 的截图也是这么说的。差异化在**你留下的痕迹**：读到哪、打了几分。

**现在的构图：左边纸上一句标语，右边一排立着的书脊 + 架板。**
（上一版是一墙封面，换构图不换主张——判据一条都没松，见下。）
右边最后一本被卡片右沿裁掉一半，那是有意的：书架不止这几本。

四条判据写在 `social-card.html` 顶部，这里只记最容易被改坏的三条：

- **痕迹不能省。** 一排光书脊又退回「书很多」了。所以书脊上挂着
  `★4` 和一条读到 62% 的进度线，值和样式**照抄应用里的真实控件**
  （`.book-rating` / `.book-progress`），**抄值不抄截图**。
  占位色相也走应用自己的 `hueOf`，不是随手挑个步长走一圈色轮——
  这几本书在真实应用里就是这个颜色。
- **全卡只有一处红，就是图标上那道朱签。** 更早那版「书斋」两个字也是红的，
  两处红互相抢；标题因此是墨色。**书脊上也别再插一条签**，同一个理由。
- **品牌标记用 `master-small.png`，卡上不许再手画一个。**
  手画的就成了第二份要跟着图标同步的东西——重画图标不会更新它，而且没人会发现。
  ⚠️ 「一方藏书印」和「文件夹里的书脊」是图标那边**否掉过**的两版，
  但那两条否决是**按 16px 判的**（印糊成红点、和资源管理器撞脸），
  社交卡最小也有 360px，不适用；适用的只有上面这条。

## 重新生成

要装 [html-shot](https://github.com/anthropics/skills) 那套（Playwright + sharp）。
**`--base build` 不能省**：字体是 `../fonts/...`，不指定根目录会逃出输入目录被归一
成 `/fonts/...`，然后静默回退到系统字体（第一次就踩了，好在它会报 `note —` 并且
退出码非 0）。

```bash
S=~/.claude/skills/html-shot

# 图标母版
node $S/render.mjs build/brand/icon.html       build/brand/master-1024.png --width 1024 --height 1024 --transparent --base build
node $S/render.mjs build/brand/icon-small.html build/brand/master-small.png --width 256  --height 256  --transparent --base build

# electron 那套：icon.ico / icon.icns / icon.png(1024) 直接落在 build/
node $S/icons.mjs build/brand/master-1024.png build --preset electron --small build/brand/master-small.png

# 社交卡（1280×640，GitHub 社交预览的尺寸，也够当 og:image）
node $S/render.mjs build/brand/social-card.html build/brand/social-card.png --base build --palette

# 小尺寸体检——改完图标**先看这张再说好了**
node $S/render.mjs build/brand/sizes.html build/brand/sizes.png --base build --dpr 2

# 社交卡的缩略图体检——改完社交卡**先看这张**：
# 它把 social-card.png 并排渲染成 500 / 360 / 260 三档（X 时间线 / Slack / 微信列表），
# 哪一档的字糊了，那一档就是噪点。
#
# ⚠️ **输出写到临时目录，别落在仓库里。** 上一版把它连输出一起提交了
# （352 KB，仓库第二大的文件），而那张图既没人引用、也没撑着任何一条写下来的
# 结论——`sizes.png` 留着是因为它撑着「.ico 里 16/32 用哪个源」那条硬结论，
# 这张没有。看完就关，要看再跑一次。
node $S/render.mjs build/brand/thumb.html %TEMP%/shuzhai-thumb.png --base build --dpr 2
```

`electron-builder` 自己会挑 `build/icon.ico`（Windows）和 `build/icon.icns`（mac），
不用改 `electron-builder.yml`。

社交预览图要**手动**传到 GitHub 的 Settings → Social preview，`gh` 命令行设不了。
