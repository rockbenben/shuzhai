# 个人评价体系 — 设计

> **状态（2026-08-20 复核）：两半都做完了。** 下面写的「本轮只实现『书评依附于库里已有的
> 书』这一半」是当时的范围；另一半（**手工添「读过但本地没有文件」的书**）后来也落地了，
> 在 `src/core/manual.ts` + `AddBookDialog.tsx`，界面上叫「添读过的书」。

**目标（用户原话）**：对所有小说进行个人评价和自定义标签，建立一个个人书库，
**避免日后重复阅读**。

用户对这个应用的心智模型是两部分：

1. 我读过的书籍记录和书评
2. 如果书评对应的书在本地有文件，书评就显示在那本书上

也就是说**书评是主体，本地文件是可选的**。本轮只实现「书评依附于库里已有的书」这一半，
但数据结构按「书评可以脱离文件独立存在」来留地基——代价几乎为零，现状已经满足
（`reading_state` 挂在 `book_id` 上与文件无关；`book.list` 是 `left join book_file`，
没有文件的书照样列得出来）。

## 需求确认的四个取舍

| 问题 | 选择 |
|---|---|
| 以前读过的书要不要批量补标 | **不特意补**，碰到「咦这本好像读过」时顺手标 |
| 「顺手标一下」记什么 | **星级 + 短评 + 标签，一次填完** |
| 标签是判断类还是题材类 | **两类都要，题材类是主力**——想靠标签把八千本按题材归类 |
| 批量怎么圈书 | **对当前筛选结果整批操作**，不做逐本勾选 |

另有两条明确否决：

- **评分不联动阅读状态。** 给「想读」的书打分不会把它改成「已读完」。理由是用户还没想好
  管理方式，不该让一个动作偷偷改另一个字段——这个项目在 `setStatus` 上踩过
  「改 A 顺带写 B、离开时不还原」的坑。
- **不做逐本勾选。** 书架分页每次 120 本，勾选天然够不到第 121 本以后；而对**整个筛选
  结果**操作才是唯一能一次覆盖上千本的做法。

## 为什么批量只能靠筛选

用户的 8172 本**全部平铺在 `D:\vault\TXT\Novals` 一个目录下，没有任何子目录**
（SQL 实测）。所以「按目录批量打标签」这条最省力的路不存在，剩下的抓手只有
书名关键词搜索——而书名其实编码了大量题材信息（重生 / 穿越 / 系统 / 华娱 /
大明 / 三国 / 火影……）。批量入口因此建在筛选结果上。

## 数据

**一条迁移**：`reading_state` 加 `rated_at`。书评集最自然的浏览顺序是「最近写的」，
而现有的 `last_read_at` 对「读过但没在这个应用里读」的书是空的——那恰好是本轮的
主要场景。这个字段以后补不回来。

其余全部复用现有结构，**不加表、不改主键**：

| 已有 | 用途 |
|---|---|
| `reading_state.rating`（real）/ `comment` | 星级、短评。real 是为了以后想要半星不用迁移 |
| `tag` / `book_tag` | 标签。`tag.name` 有 unique 约束 |
| `book.list` 已返回 `rating` / `tags` | 卡片上显示不用改查询 |
| `tagBooks(db, bookIds, names)` | 本来就收数组，批量打标签直接用 |

## 三个新 rpc

- **`tag.addByFilter(filter, names)`** — 在主进程里按筛选条件圈书，不把八千个 id
  从渲染进程传过去。**返回实际被改动的 `bookIds`**（本来就有这个标签的不算），
  界面拿着它做一次「撤销」。
- **`tag.rename(tagId, name)`** — 改名。**目标名已存在时就是合并**（把书迁过去，
  删掉空标签）。题材标签靠手打，`玄幻` / `玄幻 ` / `玄幻小说` 分裂是必然的，
  没有合并这套就会烂掉。
- **`tag.delete(tagId)`** — 连同它的所有关联一起删。

## 界面

### 单本评价浮层

卡片悬停工具条现在是「编辑 / 章节 / 改名」，加第四个「**评价**」。点开一个贴着卡片的
小浮层（不是全屏对话框——「顺手标一下」经不起一次全屏跳转）。

三样，从上到下：

1. **五颗星**：点第 N 颗给 N 分，再点同一颗清零。
2. **一句短评**：单行，回车即存。
3. **标签**：这一格是题材标签的关键，做法是**尽量不打字**——上面一排是已经用过的
   标签（按使用次数排）点一下就上，下面输入框边打边补全，补不到回车新建；
   已打上的显示成可点掉的小块。

**没有「保存」按钮**，全部即时生效。这跟设置弹窗定下的规矩一致（少一个概念）。

### 卡片上看得见

这是「避免重复阅读」真正的兑现点——信息必须在**点进去之前**出现：

- 评过分的书，封面角上显示 `★4`。用数字不用五个星形：卡片那么小，一排星形在封面图上
  糊成一团。
- **悬停 `★4` 显示短评**。「烂尾了别看」这句话不在这儿出现，整件事就白做了。
- 有标签的书，在「作者 · N 章」下面加一行显示标签（最多 3 个，多的显示 `+N`）。
  **只在有标签时才占这一行**，否则八千张卡片凭空长高一截。

### 批量打标签

筛选/搜索之后，头部显示「共 N 本」，旁边一个「给这 N 本打标签」。点开后：

1. 输入标签（同样带已有标签的点选和自动补全）
2. **预览**：列出前 20 本 + 总数，让用户确认圈对了
3. 执行后给一次「**撤销**」——`tag.addByFilter` 返回的就是实际改动的 id 列表

### 标签管理

从筛选栏的标签区进入。列出所有标签和各自的书数，可改名（同名即合并）、可删除。

### 筛选

`Filter` 加两个字段：

- `minRating?: number` — 只看几星以上
- `rated?: boolean` — 只看评价过的 / 只看还没评价的

侧栏加一档「**我的书评**」，等价于 `rated: true`，默认按 `rated_at desc` 排。

## 明确不做

- **读完自动弹「评一下」**——用户还没想好管理方式，先别加打扰。
- **半星 / 十分制**——`rating` 是 real，以后要加不用迁移。
- **手工添一本没有本地文件的书**、**扫描时按书名作者认领**——留地基不建界面。
- **逐本勾选**（见上）。
- **评分统计报告 / 年度总结**——spec §15 明确不做。

## 测试

核心逻辑全在 `src/core/library.ts`，`node:test` 直接覆盖：

- `tagBooksByFilter` 只改筛选结果内的书，返回的 id 就是实际新增的那些（已有的不重复计）
- `renameTag` 撞到已有名字时是合并：书迁过去、旧标签消失、书数是两边的并集而不是和
- `deleteTag` 连带清掉 `book_tag`
- `rated_at` 在打分和写短评时更新，清空评分时不留下孤儿时间戳
- `Filter` 的 `minRating` / `rated` 和其余条件能叠加（走 `buildFilter` 同一条路径，
  不另写 SQL——`shelfCounts` 绕开 `buildFilter` 自己写 SQL 那次教训还在文档里）
