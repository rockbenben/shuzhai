# 界面体检

这里的走查脚本都要**一个跑着的应用**（CDP），所以既不在 `npm run lint:ui` 里、也进不了 CI。
`lint:ui` 跑的是另外那组纯静态的（`dead-fields` / `dead-mounts` / `stale-refs` / `dup-decls`）。

⚠️ **这两处都不记个数。** 原来写的是「这三个脚本」和「lint:ui 跑的是另外三个」——
两个数后来都错了（走查涨到五个、`lint:ui` 添了 `dup-decls.mjs`），而这种错不报错。
要准数就看目录和 `package.json` 的 `lint:ui`。

⚠️ **你自己开着应用时，给走查实例换一个接口端口。**

维护接口默认 30036，而那个口「谁先绑上谁占着」。你的应用占着它的时候，
走查实例（就算用了独立的 `--user-data-dir`）**压根儿没有自己的接口**——
而这里的 `rpc()` 说的就是那个地址。实测后果：**每一句 rpc 都打到真实库上**
（往里面写进去过两条测试划线）。`guardTestLibrary()` 现在会拦住，
但拦住的意思是「跑不了」。要同时跑，两头读同一个环境变量：

```powershell
$env:SHUZHAI_API_PORT = '30037'
node_modules/electron/dist/electron.exe --user-data-dir=D:/tmp/testdata --remote-debugging-port=9876 .
$env:SHUZHAI_API_PORT = '30037'; node scripts/ui-check/notes.mjs
```

⚠️ **手上有第二个检出（worktree）时，先确认 9876 那头是谁。**

调试端口只认端口号，不认是谁开的。上一轮忘了关的实例、或者从别的检出起的实例，
会让你**改一次量一次、量的全是另一棵树**——`audit.mjs` 每个界面都 reload，
可它 reload 的是那个实例自己的 `dist/`。实测的样子：改完重新 build，
五个分辨率里**该消失的一条都没消失**，看起来像「改了没生效」。

`connect()` 现在会比对（`page.url` vs `process.cwd()/dist/index.html`），
不一致直接退出 1 并印出两个路径。要自己看一眼就：

```powershell
(Invoke-RestMethod http://127.0.0.1:9876/json/list)[0].url
```

## 三步跑起来

```powershell
# ① 造一个假书库（十来本，几百 KB；确切构成看它自己打印的那行）——**绝不能拿真实书库跑走查**，理由见下
node scripts\ui-check\make-testlib.mjs D:\tmp\testlib

# ② 用一个独立的档案目录开应用（不是你平时用的那个）
node_modules\electron\dist\electron.exe `
  --user-data-dir=D:\tmp\testdata --remote-debugging-port=9876 .

# ③ 跑体检
node scripts\ui-check\audit.mjs
node scripts\ui-check\keyboard.mjs
node scripts\ui-check\walk.mjs D:\tmp\testlib
node scripts\ui-check\review.mjs
node scripts\ui-check\notes.mjs
```

**`audit.mjs` 能只跑一部分**：`node scripts/ui-check/audit.mjs 760x520 全库搜索 设置`
——参数里长得像 `760x520` 的当分辨率，其余当界面名；都不给就是全量。

全量一趟**接近一小时**（每档约十分钟），而「改一处、量一次」才是这东西唯一有用的
用法：改完要等一小时才知道撑没撑破版面，等到第二次就不会再等了，
于是走查从工具退化成「发版前跑一次的仪式」。

⚠️ **写错名字会当场退出（码 2），不会静静地印一句 `0 条`**——
那句话和「全都好好的」逐字相同。点名跑的时候它先自报
「只跑点名的 N 个界面：…」，看一眼那个数对不对，再看结论。

`make-testlib.mjs` 造的每一本都对应走查里真需要的一种情况（带卷的、没有章节
标题的、书名超长的、子目录里的、只编目的 pdf），别随手删。
**每本都补到 ≥10 KB**：`scan.ts` 的收录下限是 10240 字节，小于它会被
静默跳过——这个坑在这个仓库里踩过三次。

| 脚本 | 干什么 | 退出码 |
|---|---|---|
| `audit.mjs` | 每个分辨率 × 每个界面（**具体几个看 `audit.mjs` 的 `RES` 和 `SURFACES`，这两张表一直在长**；最小那一档是 760×520，也就是 `main.ts` 里窗口的下限。界面里含**翻页模式的阅读器**——它和滚动模式走的是两套 CSS），量横向溢出 / 跑出视口 / 弹窗超高 / **主按钮要不要滚才够得到** / 点击目标 / 对比度 / 文字被硬切 / **最后一行只剩一个字** | 有问题就非 0 |
| `keyboard.mjs` | 键盘和屏幕阅读器这条线。**不记有几段**（一直在长，记了就过期）：真按 Tab 在书架上走一圈看焦点标记；开着弹窗按 Tab 看焦点跑不跑得出去、打开时进没进去；弹窗原地换一层；卡片上那排操作条在不在 tab 序里；**打分那五颗星的可及名称和「现在是几星」**；**弹窗自己有没有名字**（只有 `role="dialog"` 的话屏幕阅读器念的是光秃秃一句「对话框」，不说是哪一个——这条加进来的当天就抓到一个：内容异步到的那种弹窗，遮罩出现那一刻里面还没有标题可接）。焦点约束和接名字都在 `src/renderer/modal-a11y.ts`，一处管全部弹窗 | 同上 |
| `walk.mjs <书库目录>` | 端到端**第一次用**：加目录 → 书架铺出来 → 开书 → 读完时问了要不要记一句 → 记下来 → 「我的书评」里找得到它、短评印在卡片上 → 那一档自动按评价时间排 → 按书名搜得到（8 步） | 同上 |
| `review.mjs` | 端到端第二条：**把一批书归置好**——添读过的书（不填作者时认领已有那本）、批量打标签（**按钮上的数 = 真会改的数**、撤销只摘这次新打的）、标签管理搜索 + 改名即合并、按星级筛（界面剩的和后端算的一致）、批量改状态的预览、**备份→丢掉→恢复后书评在书架上回来了**、**划线漂了会说一句而不是凭空消失**、**「在读」不被全局排序偏好带跑**、**侧栏计数跟着横向筛选走**、**阅读器里随时记得下一句评价（不用读完）**。**要一个已经有书的库**：先跑 `walk.mjs`，或自己 `root.add` 一个 | 同上 |
| `notes.mjs` | 端到端第三条：**做笔记那条线**——给颜色起用途（黄＝好句、蓝＝待查）→ 在正文里划一段（**色块上写的是用途不是「蓝」**）→ 点它在卡上补一句笔记 → 目录上出现「划线 1」的记号 → 面板里看得见 → **切繁简把它弄漂 → 一键重新对上** → 回书架从「我的笔记」跨书找到它、点一条跳回原处 → 导出全部笔记。**然后在 PDF 查看器里把同一条路再走一遍**（文字层里选中 → 色块上写的还是用途 → 点划线开卡不是一点就删 → 卡上有「写笔记」→ 目录记号）——**这一段才是最值钱的**：两个阅读界面是两份实现，这个仓库在它们之间抓到过三次分叉，而两边各自的单元测试都是绿的。夹具那本 PDF 的书签树是 1,1,2,3，所以一条第 1 页的划线该让**头两条**目录项都带记号——那正好证明记号认的是页码不是行序。**自己清干净**：跑完把造的划线书签都删掉、繁简调回 off。⚠️ 「重新对上」那一步**「没敢动」也算过**：夹具正文是同一段重复的，锚不止一处时不动手正是判据 | 同上 |

## 五个脚本连着跑：顺序是有讲究的，而且**一次只能跑一个**

```
① walk.mjs <书库目录>   ← 必须**全新的 --user-data-dir**
② review.mjs
③ keyboard.mjs
④ notes.mjs             ← 它自己清干净，放哪儿都行；摆这儿是因为前面那两条会造出书
⑤ audit.mjs             ← 放最后：它会往库里塞 28 个标签和两条书评
```

- **一次只能跑一个。** 五个脚本连的是同一个 CDP 端口，同时跑会互相把页面
  切到别的分辨率/别的弹窗上——实测过一次：报告上一堵「没打开」「打不开」，
  看起来像应用整个坏了，其实只是两个走查在抢同一个页面。
- **`walk.mjs` 要全新的档案目录。** 它那步「读完时问了要不要记一句」依赖
  「这本书还没被评过」——跑第二遍必然红，而且**症状会飘到别的步骤上**
  （实测报的是「我的书评里找不到它」和「排序没变」，跟步骤名对不上）。
  判断依据：`加书库目录 收进来 0 本` 就说明这个档案不是新的。
- **`audit.mjs` 放最后。** 它见标签少于 20 个就补种（`seedReviewData`），
  跑完库里多出 28 个标签——不影响正确性，但会让前面几个脚本的数字对不上你手算的。

## 重启那个实例：先等进程没了，再等端口绑得上

```powershell
Get-Process electron -ErrorAction SilentlyContinue | Stop-Process -Force
while (Get-Process electron -ErrorAction SilentlyContinue) { Start-Sleep -Milliseconds 500 }
node scripts/ui-check/port-free.mjs 9876     # 等到真的 bind 得上
node scripts/ui-check/port-free.mjs 30036
node_modules/electron/dist/electron.exe --user-data-dir=D:/tmp/tdW9 --remote-debugging-port=9876 .
```

⚠️ **三层，一层比一层深，每一层都各栽过一次：**

1. **「HTTP 不应答」不等于端口空了。** 正在退出的进程还占着 socket，只是不答 HTTP——
   `curl` 超时和「没人监听」长得一模一样。照它起新进程，日志里就是一片
   `bind() returned an error`，而你在外面等一个永远不会就绪的接口。
2. **「connect 被拒绝」也不够。** 刚关掉的监听 socket 会拒绝连接、却仍占着地址。
   `port-free.mjs` 因此改成**直接试着 bind**——问的是真正那个问题，
   不是找一个和它相关的代理指标。
3. **端口空了仍然不等于起得来。** 单实例锁是**档案目录里的一个文件**，由进程持有：
   `Lock file can not be created! Error code: 32`。所以第一步是等 electron
   进程一个都不剩——`taskkill /IM` 不等人，返回时进程往往还在死。

⚠️ **档案目录一律用正斜杠。** 那个参数里的反斜杠经过一层 shell 转义就可能被吃掉，
变成一个没有分隔符的怪路径——**而应用照样起得来**，只是在一个不存在的目录里
开了个空库，`/api/stats` 报 `books: 0`，一句错都不报。
看起来和「走查库被清空了」一模一样，我据此差点去查数据库。
Windows 认正斜杠，写 `D:/tmp/tdW9` 就没这一出。
（同这个仓库里那两个路径分隔符写反的坑：**工具静默地什么都没找到，
而「没找到」看起来和「没问题」一模一样**。）

## ⚠️ 七条只有踩过才知道的

**1. 默认拒绝在真实书库上跑。** `guardTestLibrary()` 看到 100 本以上就退出——
这些脚本会点开书、翻章、改状态，那会写进 `reading_state`，**重扫恢复不了**
（实测把一本书从第 572 章点到了 485 章）。真要在大库上量性能，加 `--big`，
并且自己确认那是个副本。

**2. 探针会骗人，所以每个脚本都带自检。** 这一轮轮走查里，「量到的东西是错的」
出现了六次，每次都长得像真缺陷：
颜色解析没认 `color(srgb 0.96 …)`（把 0.96 当成 96）、
`bgOf` 不看渐变（把「白字压深色封面」算成「白字压米色纸」）、
`el.focus()` 触发不了 `:focus-visible`（报出 327 条假的「聚焦看不出来」）、
路径分隔符写反导致扫描器读不到任何文件（三段全空 = 看起来一个问题都没有）、
拿自己编的词搜 FTS（0 条 ≠ 索引坏了）、
无头窗口里聚不上焦（「失焦才保存」的输入框看起来永远在丢数据）。
**结论是「有问题」的时候，先证伪探针再动代码。**

`audit.mjs` 会先往页面里塞一个必然不合格的元素（8px 的相邻按钮 + 1.2:1 的文字），
抓不到就报错退出；`keyboard.mjs` 会检查 Tab 是不是真的走动过。

**3. 「能滚」和「找得到」是两条判据。** 「弹窗超高且不能滚」量的是溢出屏幕，
而能滚的弹窗照样可以把主按钮埋在第二屏——实测「编辑一本书」在 1280×720 下
「保存」要往下滚 449px，而书名 / 作者这些字段只在点它时才落库。所以另加了
一条「主按钮要滚动才够得到」。

**4. 在真实书库上量之前，先让机器热起来——冷缓存会伪造出一个几十倍的退化。**
拿真实库的副本（596 MB）第一次跑，量到「整页重载 → 书架铺出来」**82 秒**、
「开一本书」**20–30 秒**；同一台机器同一个库，第二遍分别是 **1.3 秒**和
**37–53 毫秒**。第一遍量的是「刚拷完 596 MB、系统缓存全冷、磁盘还在刷」。
**判据：任何吓人的数字，先拿同一件事再跑一遍当对照组，再决定它是不是缺陷。**
（这一条和 AGENTS.md 里「命中率断崖有两种成因」是同一个道理。）

**5. 固定等待是假失败的头号来源。** 同一条路径实测 1.8 秒不够、2.5 秒够——
所以 `walk.mjs` 用的是轮询（`until`），不是 `await wait(n)`。
`audit.mjs` 原来还在用固定等待，实测「书内搜索」在 1920×1080 报了一次
「没打开」、紧接着重跑就干净——现在它也改成轮询了。
⚠ **轮询只能往后延，不能提前收工**：`s.wait` 是下限，元素早出现也要等满它。
多数 surface 的 `expect` 是通用的 `.modal`，而它们的 `open` 是一串
`setInterval` 点击（「在线地址」先开「编辑一本书」，那个也是 `.modal`）——
一成立就量，量到的是链子中间那一屏，而复查照样通过，报告干干净净。
**一条偶尔变红的走查和一条永远绿的一样没用**，两种情况下人都会开始无视它。

**6. 会写库的那一条必须自己收尾。** 「自定义封面源」这个界面得先点「加一个源」
才长出来，于是走查每跑一轮就在库里留下四行（四个分辨率各一行）。
在同一个档案目录上跑几轮之后，那个弹窗比第一次高一大截——
**同一个脚本重复跑，量的已经不是同一个东西了**，而报告上一点异常都看不出来。
它的 `close` 现在会把自己加的那一行删掉。

**7.「最后一行只剩一个字」是这个界面上最常见的一类缺陷，而别的判据一条都不响。**
中文在任意两个汉字之间都能断行，所以一句话很容易折成「……当场跟着」/「变」。
没有溢出、没有截断、对比度也好好的——一轮走查里这个形状出现了三次
（书架卡片的「2 万」/「字」、设置里标签的「……每行字数」/「数」、
说明句的「……当场跟着」/「变」）。
探针按行归并 Range 的矩形，行数 ≥ 2 且最后一行窄于 1.35em 就报。
⚠ **`getClientRects()` 给的是「文本段」不是「行」**——中英混排在同一行上
也是两个矩形，第一版直接拿 `rects.length` 当行数，四个分辨率一口气
128 条假警报。自检里为此专门放了一个**必须不被报出来**的诱饵。

## 暗色外观：跑法和一条验不了的路

走查默认跑「亮」。要量暗色，跑之前把 `appearance` 写进 localStorage 再让脚本自己重载
（`novel.read-settings` 这个键，`appearance` 取 `light` / `dark` / `auto`）——
它跨重载保留，所以设一次就够，不用改脚本。

**量过了，全 0**（当时是四个分辨率 × 26 个界面，后来补到五档、界面也多了几个，
仍然全 0）。这不意外：应用配色由
`app-palette.test.ts` 守着、纸色由 `builtin-themes.test.ts` 守着（正文对比度
4.5–15、桌/纸明度差 1.5–12），颜色本身早就钉住了。暗色跑一遍是确认
「这两套颜色真的同时出现在屏幕上」，不是重新验配色。

⚠️ **「跟随系统」那一档的实时切换，从 CDP 验不了。**
`Emulation.setEmulatedMedia` 只改 `matchMedia(...).matches` 的**取值**，
**不派发 `change` 事件**——对照实验：自己挂一个一模一样的监听器，切换之后
收到 **0** 次。所以「系统半夜自己切过去，应用跟不跟」这件事在这里量出来
永远是「不跟」，而那是探针的结论不是应用的。

能验的那一半已经验了：`appearance='auto'` + 模拟系统为 dark + **重载** →
`data-theme=night`，模拟为 light → `day`。也就是说处理函数本身是对的，
剩下「事件会不会来」是 Chromium 的合同。**别照着 CDP 那个结果去「修」
`main.tsx` 里那个监听器。**

顺带一个真踩到的坑：`appearance` 的第三档在代码里叫 **`auto`**，不叫 `system`。
我按 `system` 注入测了一轮，得到「跟随系统完全不生效」，差点报出来——
无效值会静默退回白天。**注入设置之前先看一眼那个联合类型。**

## 会弹系统对话框的地方不能点

选目录、选文件、选字体这些走的是 Electron 的 `dialog`，**那是模态窗口，
一弹出来 CDP 就再也收不到任何指令**。`walk.mjs` 里「加目录」那步因此走 rpc，
其余全部走界面——能点的都点，点不了的才绕。
